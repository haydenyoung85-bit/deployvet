Security for apps vibe coded with Cursor

An app you vibe coded with Cursor can be safe, but you have to check it. The AI writes what you ask for and can miss login checks, leave keys in the wrong place, or trust user input. Review auth, keys, database rules and packages before launch.

Step-by-step checklist

  1. Ask: where does each secret key live? It should only be read on the server.
  2. Check your .gitignore covers .env files, and that none were committed.
  3. For every API route, confirm it checks the user and their rights before it reads or writes data.
  4. If you use Supabase, turn on RLS for every table and review the policies.
  5. Look for raw SQL built from user input. Use query parameters instead.
  6. Run npm audit (or your package manager's audit) and update risky packages.
  7. Check that every package the AI added is real and well known. Typos in names can pull in bad packages.
  8. Ask Cursor to review the code for security issues, then check its answer yourself. Do not trust it blindly.

FAQ

Is code from Cursor less safe than code I write?

Not always. But it is easy to accept a lot of code fast without reading it. That is where holes slip in.

Can I just ask the AI to make it secure?

It can help find issues. It can also miss them or say things are fine when they are not. Test the real app.

What is the most common problem?

Common ones are API routes with no auth check, secret keys in browser code, and open database tables.
