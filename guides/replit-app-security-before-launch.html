Replit app security before launch

Before you launch a Replit app, put every key in Replit Secrets, make sure no key is sent to the browser, lock down your admin and API routes, and check who can see your code. Replit runs your server for you, which helps, but it cannot know which pages should be private.

Step-by-step checklist

  1. Move every key and password into Replit Secrets. Do not write them in code files.
  2. Check if your Repl is public. If it is, anyone can read the code. Make sure no secret was ever in it, and rotate any that were.
  3. Make sure your server never sends secret values to the page, even in error messages.
  4. Log out and visit every admin and API route. Each should ask for login.
  5. Check that each API route also checks who the user is, not only that they are logged in.
  6. Turn off debug mode and detailed error pages in your deployed app.
  7. If your database is reachable from the internet, use a strong password and limit access.
  8. Test your deployed URL, not only the preview. Settings can differ.

FAQ

Are Replit Secrets safe?

They keep keys out of your code. They do not help if your code sends the value to the browser.

My Repl was public with a key in it. What now?

Rotate the key in that service right away. Then move it into Secrets.

Does Replit Agent add login checks for me?

Sometimes. Do not count on it. Test each route while logged out.
